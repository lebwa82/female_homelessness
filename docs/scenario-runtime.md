# Новый HTML в приложении

Реализация утверждённого HTML-сценария. Измеренные результаты приёмки и выпуска
фиксируются отдельно в `docs/acceptance-report-2026-10-03.md`.

## Где что находится

- `docs/nevidimy-bot-scenario-final.html` — согласованный исходник.
- `scripts/import_scenario.py` → `app/scenario_copy.json` — воспроизводимая сборка
  текстов и кнопок 57 экранов. HTML не выполняется и не становится системным промптом.
- `app/scenario.py` — явные переходы, варианты анкет, поля ввода и события заявок.
- `app/chatwoot/scenario_effects.py` — запись заявок, уведомления и расписание.
- `app/chatwoot/followups.py` — минутный обход отложенных опросов через API Chatwoot.
- `tests/test_html_scenario.py` — локальные регрессии с нейтральными данными.

Активный Chatwoot-контур включает новую логику; исторический standalone-контур
сохраняет прежний протокол. История остаётся в Chatwoot. Дополнительной БД,
библиотеки оркестрации для HTML не добавлено. Существующий Redis также хранит
очередь входящих событий Agent Bot (Redis Streams).

## Поведение

Категория потребности сначала открывает соответствующий каталог, затем описание
выбранной услуги. Консультация создаётся только после подтверждения. Кнопка
«Написать» ожидает текст: нажатие само по себе не создаёт пустое обращение/отзыв.
Тема юридического запроса и каждый ответ опроса сохраняются отдельно, даже когда
несколько вариантов ведут на один следующий экран.

Свободный текст продолжает обрабатываться двумя диагностическими вызовами.
Классификатор риска не определяет запросы на специалиста — это задача классификатора
намерений. Ответы ограничены нативной JSON Schema провайдера. Старый пакет markdown
skills с командами по анкетам/меню больше не подмешивается в диагностический промпт:
источник этих действий — HTML runtime. Интонация свободного ответа задана отдельно.
Явные поля темы/отзыва перехватываются только после проверки безопасности.
Действующий приоритет экстренной ветки сохранён: И6/И7 не отменяют автоматическое
оповещение. И5 — ориентир тона для свободного диалога, а не matcher ключевых слов.
И3 реализован реальными навигационными checkpoint, а не фиксированным href.

Человек доступен всегда. «Назад» меняет экран и черновик, но не удаляет историю,
заявки или выданный сертификат. Повтор подтверждения того же черновика имеет
один ключ заявки. `/clear` сохраняет эти бизнес-факты и владение разговором.
Уведомление команды не выключает бота; назначение/публичный ответ сотрудника — выключает.
Публичный ответ без назначения закрепляет диалог за отправителем. В схеме владения
v3 снятие назначения и закрытие разговора возвращают бота. Старый скрытый флаг
`human` без сотрудника автоматически исправляется при следующем событии; история
и бизнес-факты сохраняются. `/start` и старые кнопки при активном специалисте
объясняют режим; `/system_info` показывает его, не меняя форму/опрос.

Запросы и ответы видны сотрудникам как приватные заметки. Общая видимость сохранена.
Жалоба, проблема сертификата и повторный запрос отдельно упоминают команду дежурных;
замену специалиста организует команда. Известный предыдущий специалист также
упоминается при повторе запроса. Перевод между очередями и права не менялись.

## Завершение консультации

Деплой добавляет глобальный макрос **«Консультация завершена»**. Его защищённая
приватная команда принимается только от Chatwoot User, не от клиента или Agent Bot.
Она завершает заявку, снимает человеческое назначение, ставит `resolved` и возвращает
`reply_owner=bot`. Новое сообщение открывает диалог и получает ответ бота.
Обычное ручное закрытие разговора без макроса не считается оказанной консультацией.

Если активных заявок несколько, бот не угадывает завершённую: приватная заметка
покажет их ID. Сотрудник выбирает заявку приватной командой
`[women-help:consultation-completed:ID]`. Другие заявки не отменяются.
Если заявки нет, макрос закрывает разговор/возвращает бота, но опрос не придумывает.

## Встреча назначена на будущее

Закрытый чат и закончившаяся встреча — разные события. Для будущей встречи:

1. В правой панели Chatwoot откройте атрибут **«Окончание консультации (МСК)»**.
   Введите дату и время окончания: например, `05.10.2026 15:00`.
2. Если активных заявок несколько, заполните **«ID консультации»** из приватной
   заметки о заявке. Для единственной активной заявки поле можно оставить пустым.
3. Выполните макрос **«Запланировать опрос консультации»**. Приватная заметка
   подтвердит конкретную заявку и рассчитанное время опроса. Само редактирование
   атрибута ничего не отправляет и не меняет владельца разговора.
4. При переносе встречи измените время и повторите тот же макрос. При отмене —
   **«Отменить опрос консультации»**. История и заявка сохраняются.

Опрос назначается на **окончание встречи + два часа**, с переносом в дневное окно.
Планирование не помечает встречу состоявшейся. Если встреча закончилась прямо сейчас,
старый макрос «Консультация завершена» фиксирует фактическое окончание в момент
нажатия и пересчитывает ещё не отправленный опрос. Для уже прошедшей встречи можно
ввести фактическое время в поле и запланировать опрос обычным способом.
Для одной заявки опрос отправляется не более одного раза; перенос после отправки
не создаёт новый опрос. Отмену/неявку отмечает сотрудник — автоматического определения
того, состоялась ли встреча, нет. Новая консультация требует отдельной заявки.

## Опросы

- Блок 5: через 96 часов, в 10:00–20:00 МСК. Сертификат — от подтверждённой
  доставки PDF, консультация — от сохранения запроса. При сочетании услуг
  сертификат приоритетен для блока 5; консультация оценивается отдельно блоком 7.
- Одно напоминание блока 5 — через 48 часов после отправки опроса, в том же окне.
  Истёкший сертификат не получает опрос/напоминание. Любой ответ прекращает повтор.
- Блок 7: через два часа после указанного окончания встречи (или фактического
  завершения макросом), с переносом в дневное окно;
  повторного напоминания нет. После него общий блок обратной связи 6 пропускается.
  Если одновременно просрочен вопрос о связи со специалистом, блок 7 имеет
  приоритет и отменяет ещё не отправленные проверки/повторы блока 5 по этой заявке.
  Сертификатные проверки и другие заявки сохраняются.
- И4: один раз через час бездействия после первого меню `s2`, в дневном окне.
  Текст, кнопка, команда, назначение/ответ сотрудника, закрытие или откладывание
  разговора отменяют напоминание. «Назад» его не перезапускает; `/clear` разрешает
  новое напоминание после нового первого меню. Проверяются и уже поступившие
  сообщения, webhook которых ещё ожидает обработки. Повторных напоминаний нет.
- И9: при новом свободном сообщении или `/start` после 24 часов без публичной переписки. Приветствие
  добавляется к содержательному ответу, не перехватывает экстренную ветку или поле формы.

Расписание, ключи отправки и статусы находятся в custom attributes Chatwoot;
рестарт не теряет таймеры. При человеческом владении, отложенном разговоре,
незавершённой обработке входящего или открытом поле ввода опрос ждёт.
Старое незаполненное поле **закрытого** диалога не блокирует опрос после встречи.
Публикация перепроверяет владельца, ключ сообщения предотвращает обычный повтор.
Проверки новых правил: `tests/test_chatwoot_scheduling.py`; живая приёмка —
`uv run python -m scripts.run_chatwoot_acceptance --mode candidate --suites scheduling timers`.
После деплоя `--mode webhook --suites scheduling` проверяет реальную доставку команд
и сохранение расписания, не переводя часы production-процесса.

## Сертификаты и границы

Для тестового инвентаря показывается согласованный срок семь дней. Реальные PDF
не переписываются: выдача допускает только номинал 3000 ₽ и минимум семь дней
до срока поставщика. При несовпадении доступна подтверждаемая заявка на ожидание.
Ограничение одного сертификата продолжает обеспечивать существующий уникальный
индекс получателя; очистка контекста его не снимает. Коды/PDF не копируются
в навигационные checkpoint или контекст модели.

Перед внешним запуском команда должна подтвердить применимость сертификатов
к указанным товарам/услугам и реальность ответа за десять минут.

Контур рассчитан на **один процесс Agent Bot**, как сейчас в Compose. При добавлении
реплик потребуются распределённая блокировка и отдельные consumer identity. Custom attributes
не дают exactly-once отправки при сбое между HTTP-запросом и его применением.
Перебор диалогов раз в минуту подходит для текущего небольшого тестового аккаунта;
для большого объёма нужен индексированный поиск заданий.
Production webhook возвращает HTTP 204 только после записи в Redis Streams;
при недоступном Redis возвращает 503, чтобы Chatwoot повторил доставку. Восемь
последовательных рабочих очередей сохраняют порядок внутри диалога. Необработанное
событие остаётся pending и повторяется после ошибки или рестарта процесса; удаляется
только после успешной обработки. При ошибке обработчика `/healthz` возвращает 503.
Ошибки логируются без содержимого сообщений. Длительная ошибка блокирует свою
очередь, но не остальные семь. Несколько экземпляров Agent Bot пока не поддержаны.
Redis уже использует AOF; его стандартный fsync everysec оставляет окно до секунды
при аварии самого Redis/VM. Это не обещание exactly-once или нулевой потери при
физическом отказе диска; резервные копии всё равно нужны.

## Проверка и выпуск

```sh
uv run python -m scripts.import_scenario
uv run pytest -q --tb=short --show-capture=no tests/test_html_scenario.py
just check
```

`just chatwoot-acceptance candidate` проверяет локальный код в отдельном API inbox
на VM с настоящими Chatwoot и Qwen, но вызывает обработчик напрямую. После деплоя
`just chatwoot-acceptance` проверяет уже реальный webhook/Sidekiq/Agent Bot.
Подробная матрица: `docs/chatwoot-acceptance-plan.md`. Локальные API-fakes проверяют
гонки и ошибки, но не заменяют живую приёмку. Отчёты с синтетическими репликами
сохраняются в `.runtime/chatwoot-tests/<run-id>/report.json` с правами 0600, вне Git.

Дополнительная матрица `tests/test_chatwoot_ownership.py` проверяет восстановление
старых владельцев, снятие назначения без webhook, рестарт, закрытие, команды при
специалисте и запоздалые события. Отдельные регрессии проверяют передачу во время
генерации/загрузки PDF, контекст без будущих сообщений и повторы доставки webhook.
