# Chatwoot из терминала

Используем [официальный Chatwoot CLI](https://developers.chatwoot.com/cli),
не собственный клиент. На этом Mac установлен **0.7.0** в `~/.local/bin/chatwoot`.
Официальный release-архив проверен по SHA-256. Для другого компьютера установите
CLI по ссылке выше, затем выполните из корня проекта:

```sh
just chatwoot-login
just cw auth status
```

Вход использует уже существующий API-токен администратора с проектной VM.
Нужны настроенные `yc` и SSH-доступ. Перед получением токена проверяются постоянный
ID VM и её metadata. Токен передаётся CLI через закрытый stdin и сохраняется в
системном Keychain; в репозитории и shell history его нет. Команда не меняет
пароли сотрудников и не создаёт новые роли. Она заменяет текущий профиль CLI
на аккаунт 1 нашего сервера. После смены адреса повторите вход.

Без доступа к VM можно использовать штатный интерактивный `chatwoot auth login`
с собственным API-токеном из профиля Chatwoot. Не присылайте токен в переписку.

## Ежедневные команды

```sh
# Все диалоги, включая pending/resolved, без ограничения «назначены мне».
just cw convs --assignee all --status all

# Только ID — удобно для диагностики без текста и персональных данных.
just cw convs --assignee all --status all -q

# Диалоги бота; список очередей и источников.
just cw convs --assignee all --status pending
just cw teams
just cw inboxes

# Конкретный диалог (вместо 123 подставьте его ID).
just cw conv 123 messages
just cw conv 123 reply "Ответ специалистки"
just cw conv 123 reply "Внутренняя заметка" --private
just cw conv 123 assign --agent me
just cw conv 123 assign --team 2
```

`reply` без `--private` виден клиенту. Назначение сотрудника или его публичный ответ
переключает диалог в человеческий режим. Для возврата используйте штатный макрос
«Вернуть боту» в панели либо снимите назначение сотрудника.
Команды не являются dry-run: сначала проверьте ID и адрес сервера.
Не включайте `--verbose`: он выводит HTTP-данные и содержимое сообщений.

В CLI 0.7.0 `convs` и `conv view` не возвращают все custom attributes. Для точной
диагностики владения используйте `just cw api /conversations/123 -X GET -o json`
и фильтруйте только нужные поля перед выводом. В новой схеме `ownership_version=3`
`reply_owner` отражает видимое назначение; старый `human` без сотрудника автоматически
исправляется при обработке события. `/clear` не снимает реальное назначение.
Новый HTML добавляет также макрос
«Консультация завершена»: его смысл описан в `scenario-runtime.md`.

## Проверка интеграции без Telegram

Полная приёмка новой версии (платные вызовы Qwen, синтетические диалоги):

```sh
just chatwoot-acceptance candidate # локальный код + реальные Chatwoot/Qwen/S3
just chatwoot-acceptance           # обработка через уже развёрнутый webhook
```

Команда сама находит и проверяет VM, копирует код без `.env`, запускает проверки
и возвращает приватный JSON-отчёт в `.runtime/chatwoot-tests/`. Не использует
Telegram и не расходует рабочие сертификаты. PDF — нейтральный тестовый документ
без денежной стоимости, в S3 сохраняется под `test/`; тестовые диалоги закрываются,
но не удаляются. Режим candidate не доказывает правильность deployed webhook —
после выкладки обязательно выполнить второй режим.

```sh
just chatwoot-test-live          # оба набора
just chatwoot-test-live dialogue # диалог, кнопки, эскалация, человек/бот
just chatwoot-test-live queues   # маршрутизация, макросы, папки
```

Запуск проверяет адрес/ID VM и авторизацию CLI, затем использует только источник
**«Техническая проверка интеграции»** типа **Channel::Api**, без внешнего webhook
доставки. Никаких сообщений в Telegram и никаких подмен webhook.
Каждый набор создаёт отдельный синтетический контакт и новый диалог.
Клиентские сообщения входят через Chatwoot API, ответы приходят от реально
работающего Agent Bot. Ответ специалистки отправляется от авторизованного
администратора. Проверки используют официальный CLI и существующие smoke-наборы,
а не отдельную реализацию логики бота.

Проверяются история после `/clear`, старт/меню/назад, контекстные кнопки, вызов
дежурной без остановки бота, приватное упоминание команды и уведомление,
ответ специалистки без вмешательства бота, сохранение владения, явный возврат,
перевод между очередями и наличие диалога в фильтре папки. Через клиентский API
проверяется, что публичный ответ специалистки виден, а private notes скрыты.

В конце диалоги закрываются, но не удаляются; их можно открыть для проверки.
Отчёт `.runtime/chatwoot-tests/<run-id>.json` содержит ID, длительность, результаты
и безопасную точку ошибки, без токенов и текстов переписки. Код выхода 0 означает
успешные проверки выбранных наборов. Ненулевой код — ошибка/непройденная проверка,
а не повод молча менять production.

Это живые проверки: используются модель и штатные уведомления участников команд
о **тестовых** диалогах. Реальные заявки и сертификаты не создаются. Новый HTML
покрыт отдельной [матрицей приёмки](chatwoot-acceptance-plan.md): базовые smoke
не доказывают работоспособность ещё не реализованных экранов и таймеров.
