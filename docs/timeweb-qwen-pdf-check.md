# Прямой PDF-вход Qwen через Timeweb

Проверено 24 октября 2026, 03:37 MSK. Обе модели прочитали исходный PDF
через существующий Timeweb AI Gateway. Это проверка возможностей API,
не изменение модели бота и не внедрение отправки клиентских документов.

## Условия

- Endpoint: `https://api.timeweb.ai/v1/chat/completions`.
- Модели подтверждены текущим authenticated `/v1/models`:
  `dashscope/qwen3.8-flash` и `dashscope/qwen3.8-max`.
- Один искусственный PDF, одна страница, 1482 байта: случайный проверочный
  код и вымышленная дата. PDF проверен локальным парсером и рендером.
- Код и дата находились только в PDF, а не в сопроводительном вопросе.
  Каждый запрос независим, без истории других вызовов.
- В запрос шлюзу передавался исходный PDF, а не отдельно извлечённый текст
  или изображения страниц. Ответ подтвердил PDF-парсер на стороне провайдера;
  это не доказательство нативного чтения бинарного PDF самой нейросетью.
- Обычная проверка TLS, запрет перенаправлений, без автоматических повторов.
  Files API, постоянная загрузка файлов и публичные ссылки не использовались.
- Данные клиенток, реальные сертификаты и их реквизиты не отправлялись.

## Результаты

| Модель | Текстовый контроль | PDF: полный ответ | Код и дата из PDF | Подтверждение парсера |
| --- | --- | --- | --- | --- |
| Qwen 3.8 Flash | HTTP 200; 3,46 с | HTTP 200; 4,73 с | Оба точные | `pdf_page_parser.count=1` |
| Qwen 3.8 Max | HTTP 200; 1,48 с | HTTP 200; 5,94 с | Оба точные | `pdf_page_parser.count=1` |

В каждом ответе `response.model` совпал с запрошенным ID; подмена другой
моделью не наблюдалась. Каждый PDF-вызов сообщил 2287 входных и 38 выходных
токенов. Это по одному PDF-запросу на модель, **не сравнение производительности**
и не оценка качества на сканах или сложных сертификатах.

## Рабочая форма запроса

```json
{
  "model": "dashscope/qwen3.8-flash",
  "messages": [{
    "role": "user",
    "content": [
      {
        "type": "file",
        "file": {
          "filename": "synthetic-probe.pdf",
          "file_data": "data:application/pdf;base64,<PDF_BASE64>"
        }
      },
      {"type": "text", "text": "Прочитай проверочный код и дату из документа."}
    ]
  }],
  "max_tokens": 256,
  "temperature": 0,
  "enable_thinking": false,
  "include_tool_usage": true
}
```

Проверка относится к Chat Completions. Согласно
[QwenCloud PDF understanding](https://docs.qwencloud.com/developer-guides/tool-calling/pdf-understanding),
Responses API для этого PDF-механизма не подходит: HTTP 200 сам по себе
не доказывает передачу файла модели. У upstream также есть отдельная
тарификация парсинга страниц; точная стоимость этих запросов в Timeweb
в данном тесте не измерялась и не выводилась из upstream-цен.

## Граница результата

Production продолжает использовать `deepseek/deepseek-flash`.
Переменные backend до и после проверки совпали; сервисы не перезапускались,
токены и интеграции не менялись. Автоматическая отправка реальных PDF в Qwen
не включена. Действующий локальный разбор срока сертификата сохранён.

Если внедрять Qwen для чтения документов, это можно сделать отдельным этапом,
не меняя модель свободного разговора. До запуска нужны проверка на разрешённых
обезличенных образцах, ограничения размера/времени/стоимости, обработка
ошибок и решение о том, какие реквизиты разрешено отправлять провайдеру.
Содержимое PDF должно считаться данными, а не инструкциями для бота.
