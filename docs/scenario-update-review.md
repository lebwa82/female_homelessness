Источник: пользовательский `nevidimy-bot-scenario-final (8).html`.
Его содержимое перенесено в [HTML-сценарий](nevidimy-bot-scenario-final.html);
отличается только завершающий перевод строки.

**Статус:** сверка выполнена, продуктовые решения ниже подтверждены 3 октября.
Новые сценарии перенесены в локальную исполняемую логику; подробности в
[описании реализации](scenario-runtime.md). Подготовлены CLI и приёмка Chatwoot
без Telegram. Результаты выпуска и живой приёмки фиксируются отдельно в
`docs/acceptance-report-2026-10-03.md`. Этот документ — исходная сверка требований,
а не оперативный статус сервера.

## Согласованные решения

1. Свободный текст остаётся разговором с LLM; HTML управляет кнопочными ветками
   и явными полями темы/отзыва.
2. Формулировки консультантки — по новому HTML, включая «равная консультантка».
3. Оставляем обещание ответа в течение 10 минут в часы 10:00–20:00 МСК.
   Организационная обеспеченность этого SLA остаётся ответственностью команды.
4. Сертификаты — по HTML: 3 000 ₽, семь дней, один сертификат всего. При реализации
   необходимо сверять реальный номинал/срок PDF; нельзя выдумывать срок поставщика.
5. Уточнение пользователя: «Консультация завершена» закрывает разговор и возвращает
   владение боту. Следующее входящее снова обрабатывает бот. Действие запускает опрос.
6. Сохраняем общую видимость для сотрудников. При отрицательном отзыве другого
   специалиста выбирает команда вручную; автоматическое исключение не требуется.

Дополнительные уточнения: И4 автоматически не отправляем; И9 показываем при новом
сообщении после суток тишины, не подменяя ответ на конкретный вопрос. Загруженные
сертификаты тестовые; для них действует контракт HTML. Для реальных PDF номинал
и достаточный срок должны подтверждаться инвентарём, а не текстом бота.

Разделы ниже сохраняют исходное обоснование вопросов, а не повторно запрашивают
уже согласованные решения. План приёмки — [Chatwoot-only](chatwoot-acceptance-plan.md).

## Что уже есть

- Четыре вида сертификатов, подтверждение выбора, выдача PDF из приватного S3.
- Постоянный лимит одного сертификата на Chatwoot-контакт: транзакционная блокировка
  и уникальный индекс. `/clear` не снимает ограничение. Это не идентификация одной
  физической женщины при использовании нескольких аккаунтов.
- Отдельные ответы для отсутствующего и ранее выданного сертификата.
- История навигации: возврат сохраняет переписку и уже созданные заявки.
- Зеркалирование переписки в Chatwoot, уведомление команды при эскалации,
  передача владения специалистке и явное возвращение боту.
- Защита от повторной выдачи при повторной доставке событий; коды сертификатов
  исключаются из контекста модели.

Опорные файлы: `app/service.py`, `app/navigation.py`, `app/catalog.py`,
`app/chatwoot/service.py`, `app/chatwoot/certificates.py`, `app/chatwoot/queues.py`.

## Проблемы, которые нельзя исправить только заменой текстов

### 1. Свободный диалог или строгое меню

Ранее выбран свободный разговор с LLM и контекстными кнопками. Новый HTML
показывает ветку для свободного ввода, но не определяет, остаётся ли разговор
с ботом. Например, экран 3.6.1 уже подтверждает передачу пожелания команде.
Без решения можно вернуть прежний баг с навязчивым меню вместо разговора.

Предложение: HTML определяет кнопочные ветки, свободный текст остаётся диалогом;
в полях темы/отзыва текст записывается как ответ на конкретный вопрос.

### 2. Конфликт названия консультантки

HTML возвращает «равную консультантку», ранее явно заменённую на
«женщину, пережившую схожий опыт». Нужно выбрать единую формулировку.
Новый документ также уточняет специализацию — личный опыт зависимости/созависимости.

### 3. Обещания срока ответа и маршрутизация

Документ обещает десять минут с 10:00 до 20:00 МСК. Код и наличие очереди
не гарантируют дежурство, состав команды или этот срок. До подтверждения
графика предложение — писать о передаче запроса без обещания времени.

Сейчас `_persist_aid_requests` сохраняет внутреннюю заметку. Уведомление команды
вызывается отдельно при `human_handoff` / `safety_escalation`.
Обычная заявка на консультацию не эквивалентна доставленному уведомлению специалисту.
Новый ответ «Передала запрос» должен идти после надёжного сохранения и уведомления.

### 4. Номинал, срок и правила сертификата

HTML фиксирует 3 000 ₽ и семь дней с получения. Код читает номинал и абсолютную
дату из PDF; выборка допускает любой ещё действующий сертификат. Изменение
нашей даты не продлевает и не сокращает срок у продавца.

Нужно выбрать: показывать реальные данные PDF или выдавать только соответствующие
продуктовому условию сертификаты. Во втором случае нужны правила закупки/загрузки,
а не только изменение бота. Условия оплаты лекарств и Ozon Travel подарочным
сертификатом требуют подтверждения поставщиком. Попытка открыть официальную
документацию Ozon при сверке не дала доступного ответа; инструкции не подтверждены.

### 5. Завершение консультации не равно закрытию чата

Один разговор может включать несколько услуг, сертификат и несколько специалистов.
`resolved` описывает разговор целиком и сейчас не означает «консультация проведена».
Нужна отдельная отметка специалистки с идентификатором заявки: предлагается
действие «Консультация завершена» в Chatwoot. Только оно запускает блок 7.
Первоначально предлагалось отделить возврат боту. Позднее пользователь уточнил:
завершение консультации само закрывает разговор и возвращает владение боту.

### 6. Опросы и отложенные события

Активный `app/chatwoot/__main__.py` не запускает планировщик опросов. Старый
`app/worker.py` работает с прежним хранилищем и Telegram напрямую; просто
включить его в Chatwoot-контуре нельзя. In-memory задания исчезают между запросами.

Нужны постоянные задания в Chatwoot (его атрибуты сохраняются в PostgreSQL), уникальный ключ события и
восстановление после перезапуска. Срок сертификатного опроса следует отсчитывать
от подтверждённой доставки PDF, а не резервирования. Рабочее окно — явно МСК.
Не отправлять опрос поверх активного разговора со специалисткой, не возвращать
владение боту автоматически и не напоминать после отказа/ответа.

Уточнения документа:

- В блоке 5 одновременно указаны приоритет сертификата при нескольких услугах
  и отдельный вариант после состоявшейся консультации. Предложение: сертификат
  имеет приоритет для блока 5; консультация отдельно оценивается в блоке 7.
- Для блока 7 предлагается фиксированная задержка два часа с переносом в дневное окно.
- Для И4 («молчит») и И9 («вернулась через время») не заданы интервалы.

### 7. Жалоба на специалиста и доступ к ответам

Экран 7.2.1 обещает другого человека. Сейчас все сотрудники могут видеть все
разговоры; перенос в другую команду не скрывает отзыв от прежнего специалиста.
Для выполнения обещания надо исключать его из назначения и определить получателя
уведомления. Если нужна конфиденциальность жалобы, это отдельное изменение доступа;
в документе такой гарантии нет и добавлять её нельзя.

### 8. HTML-ссылки не равны действиям бота

- «Написать» в 3.5.2, 3.6, 5.1.1, 6 и 7.4 ведёт на экран подтверждения.
  В реализации сначала требуется ожидание текста. Одно нажатие не записывает ответ.
- Несколько ответов с одним адресом назначения должны иметь разные callback ID:
  иначе потеряются тема консультации и значения опроса.
- Для «Назад» действителен сохранённый путь, а не фиксированный `href` HTML.
- В общей инструкции кнопка человека постоянная, но на ряде экранов она отсутствует.
  Предложение: сохранить её всегда, поставить перед навигацией и отдельной строкой.
- Новый экран опасности предлагает передачу человеку как опцию. Не следует
  незаметно заменять им существующее автоматическое оповещение и отменять
  экстренную ветку. Нужна явная согласованная политика, не буквальное копирование.

## Порядок реализации после решений

1. Согласовать неоднозначности. Сохранить стабильные ID услуг и поддержку старых
   кнопок; не сбрасывать активные разговоры при обновлении.
2. Обновить тексты, категории, состав меню и порядок кнопок. Покрыть первый разговор
   и возвраты по каждому пути; не создавать заявки от одного показа описания.
3. Добавить консультации, темы и сбор свободных ответов. Сохранять заявки, ответы
   и уведомления с идемпотентными ключами. Кнопки и обычный текст проверять через
   действующие правила безопасности и владения разговором.
4. Связать выдачу сертификата с реальными данными PDF и согласованными условиями.
   Проверить пустой пул, истёкший срок, повторное нажатие, повтор доставки и `/clear`.
5. Добавить явное завершение консультации, постоянный планировщик и блоки 5–7.
   Проверить часовой пояс, ночной перенос, несколько услуг, отказ, молчание,
   перезапуск процесса и активного специалиста.
6. Прогнать интеграционные сценарии через Chatwoot API с тестовыми контактами;
   реальных пользователей и сообщения не затрагивать. Деплой — отдельным действием.
