# Task 10 Fix Round 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make approved live-evaluation failures actionable through aggregate-only, non-content provider diagnostics without changing product policy, provider call count, timeout, or concurrency.

**Architecture:** `app.agents` already converts provider transport and schema outcomes into audits stored by `ConversationService`. `scripts.dialogue_eval` will project a strict allow-list from those audits into typed case failure metadata, and aggregate the same categories in `EvalReport` and CLI summary. The projection will reject all content-bearing keys and preserve the existing hard-behavior projection and diagnostic health gate.

**Tech Stack:** Python 3.14, dataclasses, asyncio, pytest, Pydantic validation.

**Spec:** Parent-approved Task 10 fix round 2 instruction (2026-08-22).

## Global Constraints

- No provider, live-evaluation, Podman, or real-PostgreSQL calls in this round.
- Emit only diagnostic status, agent, transport exception class, validation field/type, and fixed output-envelope booleans; never emit values, texts, prompts, histories, response IDs, hashes, model names, token counts, or origins.
- Preserve exactly two concurrent provider calls per text turn, retries at zero, the 12-second timeout, hard policy behavior, fixture history bytes, and maximum evaluator concurrency of four.
- Do not change timeout or concurrency without new evidence.
