# Chatwoot DDS MVP — план реализации

> Для исполнителей: выполнять задачи последовательно с тестами до реализации; независимые извлечение и каталог можно выполнять параллельно. Исходный контракт — исследование DDS от 20.11.2026 и mapping 105 полей. Рабочая среда не изменяется этим этапом.

**Цель:** реализовать проверяемый локально конвейер метаданных Chatwoot → очищенный DDS и документацию, позволяющую аналитикам и ИИ правильно выбирать поля, соединения и показатели.

**Архитектура:** source READ ONLY → выбранные типизированные поля → очистка → staging → атомарная публикация DDS + checkpoint. Семь фактов с общими измерениями. Аналитики получают только разрешённые DDS/представления; применение миграций, расписания и ролей в production — отдельный этап.

**Spec:** `analytics/dds/catalog.json`, `analytics/dds/README.md` (контракт исследования от 20.11.2026).

**Стек:** Python 3.14, asyncpg, PostgreSQL (локальные интеграционные проверки на доступной версии; production PG18), JSON-каталог, SQL, pytest.

## Ограничения

- Не менять production, тариф, сервисы, текущие доступы; не выполнять удалённые записи.
- Использовать существующие зависимости проекта; не импортировать конфигурацию бота и его секреты в аналитический модуль.
- Извлекать только выбранные поля; не переносить переписки, вложения, полные JSON и реквизиты сертификатов.
- Scope account/inbox должен задаваться явно. Контакты не склеивать. Ключ JSON — только вместе с родительским диалогом.
- completed / resolved / delivered / answered не доказывают оказание помощи.
- NULL не заполнять вымышленными датами; история наблюдений начинается с первого запуска DDS.
- Один worker, 500–1000 строк на пакет, до двух соединений. Доступ к исходным данным только в read-only транзакции.

## Области проверки

1. Два account с одинаковыми ID/JSON-ключами: исключить смешение scope.
2. Повторный запуск/сбой публикации: данные и checkpoint изменяются вместе; старый срез остаётся целостным.
3. Поздняя правка/удаление дочернего JSON: upsert, tombstone после полного чтения родителя, отдельная полная сверка.
4. Неверные типы/даты/статусы: ограниченная DQ-запись без raw payload и секретов.
5. Метки и несколько фактов: предотвращение размножения строк в примерах и определениях показателей.

## Решения и статус 27.11.2026

Локальная реализация готова:19 таблиц,7 фактов,105 требований, каталог/COMMENT, словарь показателей,10 SQL-примеров. Тексты и вложения не извлекаются. Неатрибутируемый склад сертификатов не входит в scope; его остаток неизвестен. События смешанной очереди публикуются консервативно только при однозначном единственном ключе. Ссылки необработанных старых фактов окончательно пересверяются суточным full; для JOIN требуется фильтр активного измерения.

Проверки и известные исходные ошибки: [2026-11-27-dds-verification.md](2026-11-27-dds-verification.md). Production не менялся. Новые ошибки, найденные ревью, воспроизведены тестами до исправления; финальные целевые проверки прошли.
