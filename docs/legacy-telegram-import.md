# Перенос истории ручного Telegram-бота

Импорт переносит **только текстовые сообщения**, даты и внутренние уведомления
(как приватные заметки). Записи о нажатиях сохраняются текстом, без кнопок.
Файлы, авторство отдельных исходящих ответов и Telegram message ID отсутствуют
в исходной БД и не придумываются. Старые сценарии и таймеры не запускаются.

## Подготовка и безопасный импорт

```sh
# Только локальная проверка структуры и счётчиков.
just chatwoot-import-history /полный/путь/выгрузка.sql.gz --local-only

# Проверка на реальных моделях Chatwoot, транзакция откатывается.
just chatwoot-import-history /полный/путь/выгрузка.sql.gz

# Резервная копия текущего Chatwoot и импорт.
just chatwoot-import-history /полный/путь/выгрузка.sql.gz --apply
```

Адрес VM определяется через Yandex Cloud и проверяется по metadata instance ID.
Дамп **не исполняется как SQL**: читаются только COPY-данные users/messages.
Персональные данные идут на VM по SSH/stdin, не печатаются и не попадают в Git.
В stdout только счётчики и путь к резервной копии в `/opt/women-help-backups/`.
Повторный запуск сверяет сохранённые тексты, даты, направления и контрольные суммы,
не создаёт дублей. Более свежая полная выгрузка может дописать историю; изменения
уже импортированных сообщений и неполные старые выгрузки останавливают перенос.
Ошибка откатывает всю транзакцию. Исходные тестовые диалоги не удаляются.

Источник называется **«История ручного бота — Telegram ещё не подключён»**.
Он отдельный, без внешнего webhook и без Agent Bot; доступ имеют все существующие
сотрудники аккаунта. Незавершённые диалоги имеют статус Open, завершённые (CLOSE) —
Resolved. Для просмотра выбирайте все статусы. До подключения Telegram ответы
из этого источника **не будут доставлены клиенткам**.

Используется `insert_all!` внутри Rails-транзакции: это сознательно обходит callbacks
создания сообщений, которые иначе отправили бы старые ответы и вызвали бота.
Настоящие Telegram message ID не подменяются идентификаторами из старой БД.
Импорт проверен для Chatwoot 4.18.0; при обновлении сначала повторите probe.

## Проверки

Локальные тесты: `uv run pytest tests/test_legacy_telegram_history.py -q --tb=short`.
`tests/legacy_history_import_probe.rb` проверяет реальные Rails/PG-модели в
откатываемой транзакции с синтетическими данными. Проверяет повторный и добавочный
импорт, защиту от подмены/неполного снимка, атомарный откат, приватность и отсутствие
фоновых заданий. Вызывается через `remote_run(history, probe=True)` из maintained
Python-модуля; передавать только синтетическую историю из тестов.

## Переключение Telegram — отдельный этап

Не достаточно заменить токен тестового бота. Нужны токен исходного бота и финальная
выгрузка после остановки старого обработчика. Сохраните токен локально в `.env` как
`LEGACY_TELEGRAM_BOT_TOKEN`, не передавайте в чате.

1. Согласовать остановку старого процесса и его фоновых напоминаний.
2. Импортировать финальную полную выгрузку, сверить количество/содержимое.
3. Сопоставить ответственных за незавершённые диалоги с сотрудниками Chatwoot.
   Не включать ИИ в этих диалогах до назначения людей: один `reply_owner=human`
   без реального назначения в нашей системе недостаточен.
4. Подключить исходный Telegram-канал к импортированной истории, сохранив
   `contact_inbox.source_id=telegram_id` и `additional_attributes.chat_id`.
   Обновить токен приёмника; не запускать второй poller и не сбрасывать backlog.
5. Подключить Agent Bot, проверить новый входящий в том же диалоге и ответ человека,
   актуальные кнопки, завершение/возврат боту. Старые клавиатуры не импортируются.

Эти команды выполняют **импорт, не переключение**. Во время подготовительного
этапа старый бот продолжает работать; текущий тестовый бот остаётся без изменений.
